# Feature spec — T21 Durable TurnTrace + Cost Ceiling, plus the T22 backend shell

**Status**: Draft · **Branch**: `033-t21-durable-trace-shell` · **Authored by**: main loop (policy rev. 2)
**Contracts**: [`docs/contracts/turn-trace.schema.json`](../../docs/contracts/turn-trace.schema.json) (row shape) · [`docs/contracts/dev-session-api.yaml`](../../docs/contracts/dev-session-api.yaml) (shell surface) · state-machine contract §9/§11 (shell obligations)

## What / why

Two tightly-coupled backend deliverables: (1) T21 — every LLM call leaves a durable, append-only `turn_trace` row and a durable per-session cost total with a §12 ceiling behind a dark flag; (2) the imperative shell over the T20 machine, exposed as the dev-only session API — the missing backend half of T22. One stream because they share the persistence layer and the shell is the first real writer of traces.

## Functional requirements

- **FR-033-1** Migration: rich `turn_trace` columns per the committed row schema (the T05 docstring anchor names them); forward-only, additive; §3 trigger/REVOKE untouched and still effective (test proves UPDATE/DELETE still raise).
- **FR-033-2** `PostgresTraceSink` (TraceSink protocol): synchronous write before `call_model` returns; write failure → `TraceWriteError` (§1 trumps an otherwise-OK call — T04 semantics, unchanged). Populates `turn_id`, `wrapper_outcome`, `transition` when the caller provides orchestrator context.
- **FR-033-3** `PostgresCostLedger` (CostLedger protocol): running total = SUM over the session's trace rows (no second table); pre-call guard raises `SessionBudgetExceeded` when flag `enforce_session_cost_ceiling` is enabled AND total ≥ ceiling from `configs/llm-limits.yaml` (new, default 5.00 USD, §16). Flag default **false** (§9): guard logs a structured warning instead of raising.
- **FR-033-4** Flag registration per repo rules: `configs/feature-flags.yaml` entries + seeding migration rows `enabled=false` for `enforce_session_cost_ceiling` AND `enable_live_orchestrator`.
- **FR-033-5** Shell (`app/backend/services/dev_session.py` + `app/backend/api/dev_sessions.py`): implements `docs/contracts/dev-session-api.yaml` exactly. Ordering per spec-032 Clarification 4: persist state after EVERY transition, BEFORE issuing wrapper calls; `RunAssessor` commands run as FastAPI background tasks; `AssessmentCompleted/Failed` events fed back through the same transition+persist path. Command idempotency honored on re-issue.
- **FR-033-6** Gating: routes return 404 when `enable_live_orchestrator` is disabled; role-gated (reviewer/admin) when `AUTH_MODE=identity_platform`. No candidate-facing surface.
- **FR-033-7** `app/backend/openapi.yaml` regenerated; generated paths/schemas for `/api/dev/*` match the committed contract (CI regen test stays green).
- **FR-033-8** Cost-ceiling breach flow: guard raise → shell maps to machine event per state-machine contract §2 (`ABORTED(cost_ceiling)`) → `session_decision` row (`reason=cost_ceiling`) — append-only insert; observed metric name constant `techscreen_session_cost_usd` recorded for T38.

## Clarifications (decided — do not reopen)

1. Cost total derives from `turn_trace` (single source, no drift); in-process memo allowed as cache only.
2. `wrapper_outcome` closes the "trace says ok but wrapper rejected" seam recorded in specs 031/032 — the agent wrappers currently can't report it themselves; the SHELL records `rejected/contract_miss_retried` from the typed exceptions it catches. Direct wrapper self-reporting is a possible later refinement, out of scope.
3. Scripted opening/closing are delivered by the shell (transcript `role=system` entries from the repo prompt files), not via LLM calls.
4. Dev-only transcript lives inside `session_state` (the machine already accumulates what the UI needs via commands' payloads — extend the SHELL-side view assembly, not the machine). The state machine module is NOT modified in this branch; if a genuine gap blocks the shell, STOP and report — do not patch the core.

### Implementation notes (recorded during build, not design changes)

Added by `backend-engineer` while executing plan.md phases 2–5. Each is the simplest reading consistent with the two committed contracts; none reopens a decided item.

5. **The T04 seam was extended so the row contract can be satisfied — RESOLVED (contract owner, 2026-08-03).** As built, the row's three answer-side columns were unreachable: `TraceSink.write(record: TraceRecord)` is the only thing `call_model` hands a sink, and `TraceRecord` carried metadata only. The owner adjudicated a surgical, additive fix to two files:
   - **`response_text` / `parsed`:** `TraceRecord` gained `response_text: str | None` and `parsed: dict[str, Any] | None` (both defaulting to `None`, so every pre-T21 caller and test is untouched), and `call_model` populates them at its existing write site — the raw backend text plus the validated object on the ok path, whatever text came back on a schema miss, `None` for a failure that never reached the model. The frozen model stays frozen and no other behaviour in `vertex.py` changes. The sink maps them straight into the columns.
   - **Precedence:** there is none, by construction. `response_text` and `parsed` were REMOVED from `TurnTraceContext` rather than left as an override. Only `call_model` ever holds the raw bytes, so a context-supplied value could only be a reconstruction, and letting one masquerade as the raw response is exactly the corruption an audit table exists to prevent. The record and the context now own disjoint column sets; `test_the_context_cannot_supply_the_model_answer` pins that (the fields are rejected by `extra="forbid"`).
   - **`wrapper_outcome` stays nullable by design.** The sink writes inside `call_model`, before the agent wrapper has judged the output, and §3 forbids back-filling the row afterwards. NULL therefore means "the verdict was not knowable at write time", not "data missing": the definitive verdict is derivable downstream from the session's coverage markers (`assessment_failed`, the gap markers) and its `session_decision` stream. The field remains available on `TurnTraceContext` for any caller that CAN know it at write time. The row contract's description was amended in-branch to say all of this.

   Everything else the contract adds — `turn_id`, `transition` (phase + issued move + the before/after state SHAs), `prompt_version`, `system_prompt`, `user_payload` — was already written on every shell-issued call. The shell's rows are now complete audit artefacts end to end: prompt in, answer out, asserted by the SC-3 happy path.
6. **The transcript needs a column of its own** — *accepted by the contract owner 2026-08-03, no code change.* Clarification 4 puts it "inside `session_state`", but `SessionState` is a frozen pydantic model with `extra="forbid"` owned by the untouchable core, so the shell literally cannot add a key. Migration 0007 therefore adds `interview_session.dev_transcript JSONB NULL` beside `session_state` — same table, same §3 carve-out, same in-place update, written in the same transaction. The machine is unmodified and the view assembly stays shell-side, which is what the clarification is actually protecting.
7. **The ceiling flag is injected, not imported.** `PostgresCostLedger` lives in `llm/`, and `llm → services` would invert the layering rule, so `guard_session_budget` takes an `EnforcementPredicate`. The shell binds it to `is_enabled("enforce_session_cost_ceiling")`; the default (no predicate) is the §9-safe "warn, never enforce".
8. **`session_decision` had to be widened** — *accepted by the contract owner 2026-08-03, no code change.* It was `decided_by NOT NULL` with no reason column, and every decision the machine emits is authored by the system. 0007 makes `decided_by` nullable (a widening, no data lost) and adds `reason`. `RecordDecision(operator)` is emitted for the whole operator-abort family, so the row records the state's own `abort_reason` — which is how the ceiling breach lands as `reason=cost_ceiling` rather than the generic `operator`.
9. **`CostLedger.add` is a no-op.** Clarification 1 makes `turn_trace` the single source; the wrapper writes that row in the same invocation it calls `add`. Storing a second copy is the drift the clarification rules out. The method still rejects a negative charge.
10. **CLOSE completes without a model call.** `EmitScriptedClosing` is scripted, so nothing produces the `InterviewerReplyReady` edge 17 also accepts; the shell follows the scripted closing with a `TimerTick`, which is edge 17's other, tabulated path.
11. **Candidate turn ids are derived too.** §6.9 governs the machine's command ids; candidate turn ids are the shell's. They use the same recipe — `uuid5(session_id, "candidate-turn/<n>")` — so a re-POSTed turn cannot be scheduled for assessment twice.
12. **No rubric-snapshot cross-check.** Spec 032's handoff lists it for T22, but a dev session is created from an inline plan with no position template and no rubric, so the session's `rubric_snapshot` is the transitional `{}`. Cross-checking `node_id`s against it would reject every dev plan. It belongs with the real session-creation path (Tier 5).
13. **`turn_trace.agent` carries no enum CHECK.** T04 FR-008 requires a trace row even for an *unknown* agent name (that is the `config_error` outcome); a DB-level enum would block the very row the constitution demands. `outcome` and `wrapper_outcome` do get CHECKs.
14. **The 0007 downgrade leaves `decided_by` nullable.** Restoring `NOT NULL` would require deleting the system-authored decisions the pre-0007 schema cannot represent — a DELETE on an append-only table, which §3 forbids even on a local reset. A widened column is harmless (the upgrade re-applies `DROP NOT NULL` as a no-op).
15. **Agent inputs carry no wall-clock values.** The mock backend keys fixtures by canonical prompt SHA, so a timestamp anywhere in `user_payload` would make every run a fixture miss. `turn_metadata` is `{}` and nothing else in the assembled payloads reads the clock — which also means the SC-3 happy path doubles as a proof that the payloads the shell builds are byte-stable.
16. **`system` transcript entries reach the model as `interviewer` turns.** `RecentTurn.role` is a two-value Literal; the scripted opening and closing are interviewer speech the candidate read, so they enter the model's view as such.
17. **Two test-harness fixes were needed.** (a) `configure_logging` sets `cache_logger_on_first_use=True`, which freezes a module-level structlog proxy on its first call — so whichever test logged first decided whether a later `capture_logs()` saw anything. An autouse conftest fixture disables the cache for the suite. (b) The durable sink commits on its own connection by design, so the dev-session and sink suites cannot hide inside a rolled-back transaction; a shared `clean_sessions` fixture snapshot-diffs `interview_session` and purges what the test created through the §3-exempt migrator role. The suite now leaves the database byte-identical.
18. **The shell reuses the Interviewer wrapper's own two prompt helpers** (`_load_system_prompt`, `_serialize_user_payload`) to fill the `system_prompt` / `user_payload` audit columns. They are module-private only because nothing needed them before T21 — the Assessor's equivalents are already public — and re-implementing prompt assembly in the shell would silently drift from the wrapper it is auditing.
19. **Routes live under `/api/dev/...`** exactly as the contract writes them, even though the pre-existing routers (`/rubric`, `/position-templates`) carry no `/api` prefix. The contract wins; the generated `openapi.yaml` matches it path-for-path and operation-for-operation, and a contract test keeps it that way.
20. **Migration name** follows the repo ordinal convention: `alembic/versions/0007_turn_trace_audit_columns.py` (revision id `0007_turn_trace_audit_columns`).

## Success criteria

- SC-1 Trace row written for every call through the shell (incl. failed calls with non-ok outcomes); UPDATE/DELETE still blocked at DB level.
- SC-2 Ceiling test: mocked cost stream crosses 5.00 → flag off: warning only; flag on: `SessionBudgetExceeded` + `ABORTED(cost_ceiling)` + `session_decision` row (T21 acceptance from the implementation plan).
- SC-3 Full dev-session happy path against the MOCK backend in tests: create → turns → COMPLETED, every turn traced (this is the seed of T23).
- SC-4 Gates green (both DB modes); migration cycle live-verified; openapi regen equality.
- SC-5 No changes to `app/backend/orchestrator/state_machine.py`, `app/backend/agents/**`, `app/backend/llm/**` (sink/ledger are new modules implementing existing protocols), `prompts/**`.
  - **Amended 2026-08-03 (contract owner):** the `llm/**` clause is relaxed for exactly two files, `llm/trace.py` and `llm/vertex.py`, and only for the additive seam extension in note 5 (two optional fields on `TraceRecord`; `call_model` populating them at its existing write site). Everything else in `llm/**`, and all of `orchestrator/**`, `agents/**` and `prompts/**`, is untouched.
